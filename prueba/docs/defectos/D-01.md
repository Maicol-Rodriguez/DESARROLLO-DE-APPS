# Reporte de defecto

**Id:** D-01  
**Título:** Una excepción `TypeError` durante el análisis no finaliza el documento (`document_processing.py`)  
**Reportado por:** Maicol_Rodriguez · **Fecha:** 2026-11-26

## Criterio de aceptación incumplido

**Dado** un documento aceptado para análisis, **cuando** el análisis falla, **entonces** el documento debe pasar a `error` y la consulta de resultado debe responder HTTP 503 con el mensaje de fallo de análisis (`"No se pudo procesar el documento"`), sin permanecer indefinidamente en `procesando`.

## Pasos para reproducir

1. Crear un registro `{"estado": "procesando"}` para `doc-minimo`.
2. Inyectar un extractor que retorne exactamente 50 palabras: `" ".join(["palabra"] * 50)`.
3. Inyectar un analizador que ejecute `raise TypeError("tipo de salida inesperado")`.
4. Llamar a `procesar_documento("doc-minimo", b"x", ".pdf", ...)`.
5. Consultar el resultado del documento con la sesión propietaria mediante `X-Session-Id`.

## Resultado esperado

El procesador captura el fallo, registra el detalle en el log y asigna `estado="error"` con un error público genérico (`ANALYSIS_FAILURE_MESSAGE`). La consulta responde HTTP 503 con:

```json
{"detail": "No se pudo procesar el documento"}

Resultado obtenido
Antes de la corrección, la prueba de aceptación fallaba durante la ejecución y se propagaba exactamente:

Plaintext
TypeError: tipo de salida inesperado
La excepción salía de document_processing.py en la llamada al analizador antes de actualizar el estado del documento, dejando el registro en procesando y permitiendo que una consulta posterior pudiera seguir devolviendo HTTP 202.

Entorno
Windows

Python 3.10.0

FastAPI con TestClient y dobles deterministas (sin descargar modelos externos ni requerir GEMINI_API_KEY)

Evidencia
<>
pytest -q tests/test_semana8.py antes de la corrección: falló el escenario por el TypeError propagado desde procesar_documento (línea 142 en esa ejecución).

Tras la corrección, test_error_de_tipo_en_analisis_finaliza_documento_y_api_informa_503 comprueba la transición a error, el mensaje almacenado, HTTP 503, el cuerpo exacto y el uso de X-Session-Id.

Clasificación
Severidad: Media — El usuario no obtiene resultado ni estado de error y el documento permanece como procesando hasta la limpieza por expiración.Prioridad: Media (P2) — Afecta fallos de tipo inesperado durante el análisis; no afecta ejecuciones exitosas ni los errores ya contemplados.

Análisis
Caso mínimo:

Python
documentos = {"doc-minimo": {"estado": "procesando"}}

def extraer(_contenido, _extension):
    return " ".join(["palabra"] * 50)

def analizar(_texto, _tokenizer, _model):
    raise TypeError("tipo de salida inesperado")

Causa: procesar_documento convertía ValueError y un conjunto acotado de excepciones a estado="error", pero no contemplaba TypeError; al ocurrir fuera de una captura coincidente, la excepción escapaba antes de actualizar el registro.
