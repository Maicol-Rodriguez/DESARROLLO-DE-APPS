2. ETAPA 1: CONFIGURACIÓN BASE Y CLIENTE HTTP
--------------------------------------------------------------------------------
Archivos creados / modificados:
- src/environments/environment.ts: URL base configurada a http://20.20.1.157:8000/api.
- src/environments/environment.prod.ts: Configuración para producción.
- src/app/core/services/ui.service.ts: Servicio para mostrar notificaciones flotantes (Toasts),
  ventanas de alerta (Alerts) y barras de carga (Loading) usando controladores de Ionic.
- src/app/core/interceptors/auth.interceptor.ts: Interceptor funcional HttpInterceptorFn que:
  * Agrega headers "Accept: application/json".
  * Inyecta el encabezado "Authorization: Bearer <token>" de forma automática a cada petición.
  * Captura errores HTTP globalmente:
    - 401 (No autorizado / token expirado): Limpia localStorage y redirige a /login.
    - 400 (Regla de negocio inválida): Muestra mensaje de la API.
    - 403 (Acceso denegado / cuenta pendiente de aprobación): Alerta al usuario.
    - 409 (Conflicto de concurrencia al tomar viaje): Notifica que el servicio ya fue tomado.
    - 422 (Error de validación de Laravel): Muestra los campos inválidos en pantalla.
    - 0 (Error de conexión / servidor caído / CORS): Mensaje amigable de fallo de red.
- src/main.ts: Registro de provideHttpClient(withInterceptors([authInterceptor])).
- src/app/home/home.page (.ts, .html, .scss): Pantalla de prueba con botones para testear 
  la conexión a la API y la intercepción de errores en vivo.

5. ETAPA 3: GUARDS DE RUTAS Y REDIRECCIÓN POR ROL
--------------------------------------------------------------------------------
Archivos creados / modificados:
- src/app/core/guards/auth.guard.ts:
  * Protege rutas privadas. Si no hay token, bloquea el acceso, muestra un Toast 
    informativo y redirige al /login.
- src/app/core/guards/role.guard.ts:
  * Control de acceso basado en roles (RBAC). Compara el rol del usuario con

    muestra alerta de acceso denegado y lo devuelve a su panel correspondiente.
